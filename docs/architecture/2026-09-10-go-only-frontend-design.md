# Go 独立前端设计

## 目标

新建 `ai-frontend-service`，作为仅服务于 Cling 三项基础创作能力的独立 Web 前端。上线后的请求直接发送至 Go API Gateway；Node 后端不在该前端的请求路径中。

本项目只覆盖：账号、模板、素材、文生图（T2I）、模板图编辑（I2I）、图生视频（I2V）、创作状态和支付入口。Animate 及其历史任务不迁入。

旧项目 `ai-host-v2-platform-main` 与 `ai-business-service` 在本前端重构期间均为只读参考：不得修改其前端、Node 后端、Go 后端、配置或业务数据。新项目通过已冻结的 Go HTTP 合同保持业务语义，不复制旧项目的实现代码。

## 不变的业务规则

- 用户选择产品模板，不直接选择技术原子；Go 内部再编排 `text_to_image`、`image_edit`、`image_to_video`。
- 文生视频先生成首帧，再调用图生视频；前端不发起独立 T2V 技术请求。
- 生成创建接口是唯一门禁。前端不以余额预检查决定是否可提交。
- 未绑号与需要 VIP 均返回 HTTP 403，但使用不同业务码；余额不足返回 HTTP 402。
- 预扣、失败冲正和审核没收完全由 Go 处理；前端只呈现最终状态。
- 会话、账户、账本、支付回调和生成回调均为 Go 自有事实，不读取 Node 登录态或钱包。

## 架构

```text
页面与组件
    ↓
features（账号、模板、素材、创作、支付）
    ↓
api（Go API 类型、请求客户端、错误映射）
    ↓
Go API Gateway
    ↓
Go 身份、权益、账本、创作、支付领域 → 现有生成中台
```

`features` 不直接调用 `fetch`。每个业务模块仅依赖对应的 API 端口和页面状态；认证令牌由 `api` 层统一添加，HTTP 与业务错误由统一映射转换为可展示的领域错误。

每个文件只负责一个边界：页面负责组合、feature 负责交互状态、`api` 负责协议、`components` 负责纯展示。涉及业务规则、协议限制、安全边界或非直观状态转换的代码必须使用简体中文注释说明“为什么”；不为显而易见的语法逐行添加无意义注释。

## 首批模块

| 模块 | 职责 |
|---|---|
| `app` | 路由、应用装配、会话恢复和全局错误边界。 |
| `api` | 可配置的 Go API 基地址、鉴权请求、响应解析、错误码映射。 |
| `features/auth` | 注册、登录、移动端游客、当前用户及绑定账号引导。 |
| `features/templates` | 只读模板目录、SFW/NSFW 可见性及模板版本展示。 |
| `features/assets` | 素材选择、上传状态和可用于 I2I/I2V 的资产引用。 |
| `features/creation` | T2I、模板 I2I、模板 I2V、文生视频编排入口、状态轮询与结果展示。 |
| `features/payment` | 商品选择、收银台跳转、内购回执提交和到账状态。 |
| `components` | 无业务副作用的表单、状态、结果和提示组件。 |

## Go API 对接边界

前端通过环境变量 `VITE_GO_API_BASE_URL` 指向 Go Gateway。开发环境默认为本机 Go 地址；构建产物不内置 Node 地址或 Node API 密钥。

第一批复用已存在的 Go Gateway 精确路径：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/guest`
- `GET /api/auth/me`
- `POST /api/chat/image/async`
- `POST /api/images/statuses`
- `GET /api/images/:id`
- `POST /api/chat/video`
- `POST /api/chat/videos/status`
- `GET /api/chat/video/:id`
- `POST /api/wallet/create-external-checkout`
- `POST /api/wallet/verify-purchase`

素材上传和模板目录在 Go API 中尚未形成可供新前端使用的公开最终协议。因此前端项目先定义类型化端口和受控占位页，不得借用 Node 上传或 Node 模板接口；对应 Go API 合同完成后再启用页面提交。

## 状态与错误呈现

创作状态只从 Go 的任务状态接口读取。前端允许有限次数的轮询和退避，页面刷新后依据任务 ID 恢复状态；不推断扣费、退款或审核结果。

错误映射至少区分：

| HTTP 状态 | 业务结果 | 前端动作 |
|---|---|---|
| 401 | 会话无效 | 清除本地会话并进入登录页。 |
| 402 | 余额不足 | 保留输入，展示充值入口。 |
| 403 未绑号 | 游客需绑定账号 | 进入绑定账号流程。 |
| 403 需 VIP | 权益不足 | 展示 VIP 商品入口。 |
| 409 | 幂等键与请求冲突 | 提示用户不要重复修改并重试同一任务。 |
| 5xx | 系统或依赖失败 | 保留输入，展示可重试提示。 |

## 迁移与安全

1. 新项目先以本地 Go Gateway 联调，不修改旧 `frontend/` 或 Node 后端。
2. 旧前端保持可运行，作为过渡期回退页面；新前端不向 Node 发请求。
3. 每个页面以真实 Go API 合同测试、浏览器端流程测试和失败态测试验收。
4. 在素材、模板、真实支付和真实生成中台的测试环境验收完成前，不将新前端用于生产流量。

## 验收标准

- 构建产物中不存在 Node 后端基础地址、Node 钱包客户端或 Node 登录 API 调用。
- 注册/登录/游客、T2I、模板 I2I、I2V、状态读取和支付入口只通过 Go API 客户端访问。
- 前端不以本地余额判断阻止创建；准确展示 Go 返回的 401、402、403、409 和 5xx。
- 未实现的素材上传、模板读取或外部支付不会静默回退 Node，必须明确显示“暂不可用”。

## 基础层实施状态（2026-09-10）

已完成独立工程、Go HTTP 客户端、Go 自有登录会话、自由文生图状态读取、本地支付入口和 Go-only 静态审计。模板目录、素材资产、游客绑定公开入口、权益读取、真实 PayCores/IAP 以及真实生成中台回调仍依赖各自的 Go 合同；对应页面保持封闭，不能用旧 Node 接口临时替代。
