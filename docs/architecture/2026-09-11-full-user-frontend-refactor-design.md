# Cling 用户前端完整重构设计

## 1. 目标与约束

本次在独立项目 `ai-frontend-service` 中重构现有面向普通用户的 Web 前端。新前端仅调用 `ai-business-service` 提供的 Go API，不再把旧 Node 后端作为运行时依赖；旧项目 `ai-host-v2-platform-main/frontend/`、旧 Node 后端及其业务语义均不修改。

重构的目标是完成用户侧产品体验的平移与收敛，而非把旧页面逐文件复制。生成能力统一收敛为以下 3 类：

1. 文生图（T2I）。
2. 模板图编辑（I2I），用于脱衣、换装、换脸等仍保留的模板能力。
3. 模板图生视频（I2V）。文本生成视频由前端选择模板后请求 Go 编排；Go 先生成首帧，再提交图生视频原子能力。

`Animate` 已废弃：不迁移页面、导航、任务创建入口或历史任务入口。旧深链只能跳转至视频创作首页，且不会触发新任务。

本期不包含 `admin/` 管理后台，不连接真实生成中台、真实 PayCores、商店真实内购或生产环境。用户当前不使用 Git，本项目不提交、不推送。

## 2. 不可改变的业务语义

- 用户选的是产品模板，而不是 T2I、I2I、I2V 等技术原子；前端只表达模板、素材与意图。
- 创建生成的 Go 接口是唯一门禁。前端不得预先用余额或本地每日额度阻止提交，避免并发下的重复免费额度问题。
- 游客必须绑定账号后才能生成；绑定是升级同一个用户，不创建新用户。
- 未绑号与需要购买 VIP 均为 HTTP 403，但业务码不同；余额不足为 HTTP 402；会话无效为 HTTP 401。
- Go 负责占位、预扣、提交、回调、失败冲正、审核没收和账本。提交生成中台失败或尚未回调而失败时立即退钻；审核没收不退款。前端只显示 Go 返回的事实状态。
- SFW/NSFW 可见性由 Go 决定：审核用户只看安全内容；同一模式下 Web、iOS、Android 使用同一模板合同。
- 视频时长价格固定：5/10/15 秒分别为 50/100/150 钻；图片为 20 钻。VIP 每日 10 张图、3 条视频、50 钻，首月双倍；余额为 0 但仍有每日免费额度时允许生成。每日额度以首次记录的用户时区切换。
- 支付只认 Go 自有账本和支付回调的幂等结果；充值可使用现有 PayCores 与商店内购，但新前端不读取或写入旧 Node 钱包。

## 3. 迁移范围

### 3.1 明确迁移

| 领域 | 用户可见能力 | 新模块 |
|---|---|---|
| 应用壳 | 首页、响应式导航、语言前缀、加载态、错误页、PWA 安装引导 | `app`、`features/shell`、`features/localization` |
| 认证与账户 | 登录、注册、游客、绑定账号、会话恢复、资料、安全、关联账号、通知与分享设置 | `features/auth`、`features/account` |
| 创作工作室 | T2I、模板 I2I、模板 I2V、文本视频首帧编排、素材、任务状态、作品结果 | `features/creation`、`features/templates`、`features/assets`、`features/works` |
| 钱包与权益 | 余额、账本、VIP、每日额度、充值、支付结果、受控内购凭据提交 | `features/wallet`、`features/payment` |
| 作品与社区 | 个人主页、作品历史、发现、作品详情、通知、邀请、反馈、消息/聊天（若 Go 合同存在） | `features/profile`、`features/discover`、`features/notifications`、`features/social` |
| 公共内容 | FAQ、隐私、条款、内容政策、PWA 落地页、邀请页 | `features/public-pages` |
| SEO 内容 | 模板、提示词、博客、角色和公开落地页的服务端渲染或静态预渲染 | `apps/web-ssr`、`features/seo` |

### 3.2 需核实活跃度后才迁移

下列旧页面在源码路由中仍可访问，但当前没有足够证据证明仍有真实用户流量。先保留旧站入口，不复制到新站；待根据访问数据、投放链接和产品负责人确认后再决定迁移、归并或下线：`AIBody`、`AIPose`、`ViewShift`、`Anime`、`Enhance`、独立工具聚合页、产品站变体（`spicy-image`、`spicy-video`、`ai-tools/*`）、广告预览页与角色聊天。

其中脱衣、换装和换脸不属于待定的独立生成技术：若业务确认仍启用，统一作为模板 I2I 的模板项迁移，不生成额外的技术入口。

### 3.3 明确排除

- `admin/` 管理后台。
- Animate 的页面、导航、创建接口和任务列表入口。
- 旧 Node 前端/后端的代码、配置、会话、钱包与支付写入。
- 真实中台、真实支付渠道、生产部署和生产数据迁移。

## 4. 目标工程结构

```text
ai-frontend-service/
├── apps/
│   ├── web/                     # 用户 SPA：需登录的互动体验
│   └── web-ssr/                 # 公共 SEO 内容的 SSR/预渲染入口
├── src/
│   ├── app/                     # 路由、Provider、错误边界、启动编排
│   ├── api/                     # Go HTTP 客户端、类型、鉴权、错误映射
│   ├── components/              # 无业务副作用的通用组件
│   ├── features/                # 按业务领域划分的页面、状态与 API 端口
│   ├── shared/                  # 类型、工具、常量、可访问性与测试辅助
│   └── styles/                  # 设计令牌、全局样式与主题
├── docs/architecture/           # 架构、合同和迁移说明
└── scripts/                     # 本地校验与静态审计脚本
```

当前项目先保留单个 Vite 应用的构建入口；当 SPA 与 SSR 的共享组件和构建配置稳定后，再按上图拆为 `apps/web` 与 `apps/web-ssr`。这样避免在页面迁移前引入不必要的 monorepo 复杂度，同时目录边界从第一天起保持兼容。

每个 `features/<domain>` 内部采用相同结构：`pages/` 负责页面编排，`components/` 负责领域组件，`api/` 负责该领域的 Go 合同，`model/` 负责状态与类型，`__tests__/` 负责领域验收。页面不得直接调用 `fetch`；共享 HTTP 客户端统一添加 Go 会话和错误映射。关键业务边界、并发与安全原因必须使用简体中文注释说明“为什么”。

## 5. 路由与旧功能映射

| 旧入口类别 | 新入口与行为 |
|---|---|
| `/video`、`/create/video`、`/photo-to-video` | `/studio/video`；选择模板后提交 I2V。文本视频在 Go 内完成首帧再 I2V。 |
| `/image`、`/create/image`、`/image-generator`、`/dress-up` | `/studio/image`；普通创作进入 T2I，换装等进入对应模板 I2I。 |
| `/create/undress`、`/undress`、`/ai-undress`、`/ai-clothes-off` | `/studio/edit/<template>`；只在模板仍启用时可见。 |
| `/faceswap`、`/face-swap`、`/create/faceswap` | `/studio/edit/<template>`；只在模板仍启用时可见。 |
| `/create/animate` | `/studio/video`，仅跳转，不带自动提交参数。 |
| `/profile`、设置和通知 | `/me`、`/settings/*`、`/notifications`。 |
| `/recharge`、`/pricing`、加密支付回跳 | `/wallet`、`/wallet/recharge`、`/payment/result`。 |
| `/discover`、作品详情、邀请、反馈 | `/discover`、`/works/:id`、`/invite/:code`、`/feedback`。 |
| FAQ、协议与政策 | `/faq`、`/privacy`、`/terms`、`/content-policy`。 |

旧 URL 只在新前端的兼容路由层做明确、无副作用的重定向；兼容层不能复制旧页面逻辑、不能调用 Node API，也不能恢复 Animate。

## 6. Go API 边界与数据流

```text
浏览器页面
    ↓（类型化 API 端口、幂等键）
Go API Gateway
    ├── 认证与用户状态
    ├── 模板与内容可见性
    ├── 素材归属与上传
    ├── 创作编排、预扣、冲正、审核
    ├── 钱包、VIP、每日额度、账本
    └── 支付回调与内购验证
          ↓
     外部生成中台 / PayCores / 应用商店
```

前端传递用户意图、已校验素材引用、模板版本与幂等键；不得向生成中台直接发送钻石、VIP、余额或旧 Node 会话。Go 提交中台时必须携带 Go 自有回调地址，前端不会接触该地址或中台默认回调域名。

Go API 合同按领域落在 `src/api/<domain>/`。新增页面之前必须先存在对应 Go 合同；缺少合同的功能显示明确的不可用状态，绝不临时回退到 Node。

## 7. 分批迁移与验收门

| 批次 | 内容 | 进入条件 | 验收结果 |
|---|---|---|---|
| 0 | 现有基础层整固：应用壳、路由、API 客户端、会话、错误边界 | 已有本地 Go Gateway | 构建、单测、Go-only 静态审计通过。 |
| 1 | 模板、素材、三类创作工作室与作品结果 | 模板/素材/创作 Go 合同冻结 | 覆盖游客、封禁、SFW、403、402、预扣失败和回调状态。 |
| 2 | 钱包、VIP、账本、充值和受控内购 | 权益/支付 Go 合同冻结 | 只以 Go 账本与幂等回调确认到账。 |
| 3 | 用户中心、历史作品、通知、发现、邀请、反馈 | 对应 Go 查询与写入合同冻结 | 页面刷新后状态可恢复，越权访问不可见。 |
| 4 | 公共页、PWA、语言路由与 SEO SSR/预渲染 | 公共内容模型确定 | 公共内容可抓取，登录态页面不泄露私人数据。 |
| 5 | 待核实旧工具 | 有真实使用证据和 Go 合同 | 每个工具要么归并为模板，要么明确下线，不复制旧技术入口。 |

每批次都保留旧前端作为只读参考和回退来源；新前端仅在本地联调环境验收，未满足该批次门禁不得扩大范围。

## 8. 测试、可维护性与回退

- 单元测试：错误映射、路由兼容、模板可见性、金额与权益展示、表单保留逻辑。
- API 合同测试：对 Go Gateway 的请求体、错误码、幂等键、任务状态与分页结果。
- 浏览器流程测试：游客绑定、登录、T2I、模板 I2I、文本视频首帧→I2V、图片 I2V、402 充值、403 升级、失败冲正后的结果读取。
- 静态审计：构建产物与源码不得包含旧 Node API 基地址、Node 钱包客户端或 Node 登录调用。
- 可访问性与响应式测试：导航、表单、任务状态和错误提示必须可键盘操作，并覆盖移动端尺寸。

新站每批次通过本地验收后才接收相应页面流量。出现问题时，将路由入口恢复为旧前端或暂停新入口；不对旧项目做代码回滚，也不通过接回 Node API 临时修复。

## 9. 成功标准

- 新前端完整覆盖除管理后台、Animate 和经核实未使用工具之外的用户端主业务。
- 生成页面只暴露 T2I、模板 I2I、模板 I2V 三类产品能力；文本视频遵循首帧后 I2V 的业务链路。
- 所有运行时业务请求只指向 Go API；旧 Node 前端和 Node 后端不被修改。
- 权益、支付、生成状态和内容可见性全部以 Go 返回的业务事实为准。
- 目录以领域模块组织，公共代码和 API 合同不与页面混杂，复杂业务原因均有准确的简体中文注释。
